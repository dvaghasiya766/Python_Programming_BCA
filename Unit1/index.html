02 · HISTORY

Python Genesis

Python was developed by Guido van Rossum, a Dutch programmer, in the Netherlands.

Work on Python began in December 1989 at the Centrum Wiskunde & Informatica (CWI).

It was conceived as a hobby project to succeed the ABC programming language and address some of its limitations.

09 · PROGRAMMING RULES

Syntax and Semantics

Syntax

Syntax refers to the rules governing how a programming language must be written.

If the rules are violated, the program can produce a syntax error.

# Syntax error example
if x > 10
    print(x)

Semantics

Semantics refers to the meaning or intended behaviour of a program.

A program may have valid syntax but still produce the wrong result because its logic is incorrect.

# Syntactically valid
area = length + width

# Intended calculation
area = length * width
Remember: Syntax asks "Is the code written correctly?" Semantics asks "Does the code mean what we intended?"
10 · PYTHON VOCABULARY

Keywords vs Identifiers

Feature Keywords Identifiers
Definition Reserved words with fixed meanings. Names created by the programmer.
Creation Predefined by Python. Created by the developer.
Rules Purpose cannot be changed. Must follow identifier naming rules.
Examples if, return, class student_name, total_marks
IDENTIFIER RULES

How to name identifiers

01 Begin with a letter or underscore (a-z, A-Z, _).
02 Use only letters, digits and underscores. Spaces and symbols are not allowed.
03 Do not begin an identifier with a digit.
04 Identifiers are case-sensitive: name and Name differ.
05 Do not use Python keywords such as if, class or return.
06 Choose descriptive names, preferably in snake_case.
Recommended pattern lowercase_words_joined_by_underscores

Example

student_name = "Rahul"

if student_name:
    print(student_name)

Here, student_name is an identifier and if is a Python keyword.

VALID IDENTIFIERS
student_name _total marks2
INVALID IDENTIFIERS
2marks student-name class

11 · DOCUMENTATION

Comments vs Docstrings

Feature Comments Docstrings
Purpose Explain code, logic or implementation details. Provide formal documentation.
Syntax # comment Usually written using triple-quoted strings.
Runtime Ignored as comments by Python. Can be retained as documentation associated with objects.
Accessibility Read directly in source code. Can be accessed through mechanisms such as __doc__.

Example

# Calculate total marks

def calculate_total(a, b):
    """Return the total of two numbers."""
    return a + b
